開始日: 2026-10-15（日本時間）

## 実行契約

- オーケストレーター: 主エージェント。設計・指示・レビュー・統合・記録を担当。
- 作業エージェント: GPT-6.1 Sol、推論low。割当範囲内で実装と検証を担当。
- 計画: [移行計画](mcp_free_skill_migration_plan.md)。既存データの変更とMCP登録解除は今回の自動移行対象外。
- 開始時の未コミット内容: `.codex/`（ユーザー追加のオーケストレータースキル）と`docs/plans/`（計画書）。保持する。

## サイクル1: 現状固定と独立基盤

目的: 既存のMIDI処理をMCPから分離するため、業務処理の入口と保存の契約を定め、並行して実装・調査する。

| 担当 | 書込可能範囲 | 成功条件 | 状態 |
|---|---|---|---|
| 仕様調査 | `docs/plans/current_behavior_inventory.md` | 全操作、状態、副作用、テスト制約を根拠付きで列挙 | 採用 |
| エンジン抽出 | `src/engine.ts`、`tests/engine_*.test.ts` | MCP importなし、同一runtime内で既存操作を呼出可能、dispose可能 | 条件付き採用、録音精度を追加修正 |
| 保存基盤 | `src/storage.ts`、`src/dataMigration.ts`、`tests/storage_v2*.test.ts`、`tests/data_migration*.test.ts` | 固定manifestの明示選択、原子的更新とロック、非破壊の移行診断 | 条件付き採用、生成ファイルの安全な登録を追加 |
| オーケストレーター | 計画・実行記録、統合判断 | 境界と契約を固定し、差分・結果をレビュー | 実行中 |

共通契約:

- `createMidiEngine()`を`src/engine.ts`からexport。`call(name,args)`はPromiseでplain JSONを返し、`dispose()`はタイマー・ポートを閉じる。エンジンは環境変数で与えたデータ領域を使用する。
- 旧MCP入口とスキルは比較用に維持。新エンジンはMCPの初期化、tools/call、contentラッピングを実行しない。
- 保存は旧MCPテストのPID別既定を一旦維持。新CLIは`MIDI_TOOL_DATA_DIR`を実際のdata領域として設定し、固定manifestを選択する。
- 共通設定、依存ファイル、旧スキルへの同時書込みは禁止。ビルドは並行変更が揃ってから統合実施する。

判定: `pass_with_notes`。主エージェントによる確認で新エンジン・保存・移行の3ファイル11テストが合格。旧経路の基準として別途9ファイル14テスト合格。録音と再生の既存欠陥は未完了として次サイクルで解消する。全テスト／実機の合格とは扱わない。

## サイクル2: CLIと演奏品質

| 担当 | 書込可能範囲 | 成功条件 | 状態 |
|---|---|---|---|
| CLI担当（仕様調査担当を再利用） | `src/cli/`、`src/local/`、`tests/cli_*.test.ts` | 別CLIからfileIdとcaptureIdが継続し、安全に停止・再起動できる | 実装・レビュー中 |
| エンジン担当 | `src/engine.ts`、`tests/engine_recording*.test.ts` | NoteOffと保持ノートが保存長に反映され、保存が一度だけ行われる | 実装中 |
| 保存担当 | `src/fileStore.ts`追加後、`src/playbackPlan.ts`・`src/playbackRuntime.ts`・対応テスト | CC/program/PBを含む共通再生計画と安全なスケジューラ | 実装中 |

設計契約は[CLI・ランタイム契約](cli_runtime_contract.md)へ分離。MCPの旧通信は比較用途に限定し、新しいCLIとローカル制御には含めない。

レビュー指摘と対応方針:

- 既存の再生完了判定が先読み予約時点でポートを閉じていた。実送信終了を待つ実装とfake clockテストを要求。
- 旧録音はNoteOffを無視して固定長にしていた。入力コールバックのイベントから実SMFを読戻す検証を要求。
- 固定manifestだけでは同名MIDIの競合を防げない。データ全体の書込ロックと安全な名前・排他的作成を追加。
- CLI起動ロックの経過時間だけによる削除を差し戻し。所有者確認、異常終了、UTF-8、停止失敗時の後始末も確認対象。
- 削除済みmanifestの古いキャッシュを返す旧挙動は廃止し、破損manifestは上書きせずエラーにする。

次候補: 新エンジンへの安全保存／再生モジュール統合、スキル配布、MCP依存撤去と回帰検証。

## サイクル2のレビュー結果

主エージェントの統合実行で11ファイル38テストが合格。CLIの別プロセス実行、保存競合、録音NoteOffの長さ、先読み再生、完了結果の永続化、SIGKILL後の中断判定を確認した。追加実装が続くため最終合格数ではない。

判定: `pass_with_notes`。録音・保存・CLIを採用し、スキル配布と最終統合へ進む。レビューで追加した次の課題は最終検証前に解消する。

- セッションの待機状態と保存中状態も、異常終了時に中断として扱う。
- ファイルの末尾にあるCCやstate-onlyファイルを再生計画から落とさない。
- CLIが送信失敗をdone=trueだけで成功扱いしない。
- 同時起動ロックの回復で、新しく取得された別所有者のロックを削除しない。

## 最終統合と受入判定（2026-10-15）

判定: **pass_with_notes**。MCP非依存の標準CLIとスキル配布物v0.2.0を採用。ユーザーへの追加確認を挟まず、依存撤去・生成・検証まで実施した。コミットと既存データの実移行は実施していない。

### 主エージェントによる独立した検証

- `npm test`: クリーンビルド後、19ファイル73テスト合格。CLI、永続化、保存競合、データ移行、編集、録音、再生、配布、コーデック、直接API、ワークフロー、純粋なScore変換を実行。
- `npm run build`と`npm start -- --help`: 成功。標準起動がCLIとなり、MCP初期化やMCP ready通知を出さない。
- `node scripts/package_skill.mjs`: 新スキルを再生成。到達可能な18コードモジュールを収録し、旧入口・MCP SDK・生成済みMIDI・manifestを除外。
- `quick_validate.py skills/midi-tool`: 合格。
- `npm prune --ignore-scripts --no-audit --no-fund`後の`npm ls --omit=dev --depth=0`: 実依存は`midi@2.0.0`、`midi-file@1.2.4`、`zod@3.25.76`のみ。ソースとroot／新スキルの依存ロックにSDK参照なし。
- 別の一時領域へスキルをコピーし、新規`npm ci --ignore-scripts`から作曲→読戻し→500ms dry-runを確認。元リポジトリへのnode_modulesリンクなしで別CLIキャプチャ、停止、永続結果の再読込も成功。
- `node scripts/verify_native_midi.mjs --run`: 作業担当の結果に加えて主エージェントも再実行して合格。私有仮想ポートのみを使用し、同時稼働カウンター、実送信バイト、録音57bytes／6イベントを確認。
- 追加の実CLI実機検証: 私有仮想SOURCE/SINKで`play-record`と`record --duration-ms 1000`を実行。`workflow.mid`と`timed.mid`を各45bytesで保存し、指定名、実送信7メッセージ、録音ノートのチャンネルと正の長さを確認。仮想ポートと一時データはfinallyで清掃。
- `git diff --check`: 合格。既存`data/`と旧スキル`data/`に追跡対象の差分なし。ユーザー追加の`.codex/`を保持。

### 明示した制約と互換変更

- 旧MCP通信のテストは履歴参照用に保持し、標準テストから除外。73件は現行のMCP非依存テストであり、旧スイート全件合格の主張ではない。
- 調号・拍子・テンポはコーデックで元トラックと時刻を保持する。再生計画はテンポマップを使用し、CC／program／PB／aftertouchも送出する。
- 既存の小節編集は最初の拍子を基準にする。清掃は変化メタを縮約し、重複CC範囲は和集合にしない。これらはREADMEと操作説明に記載した既存仕様上の制約。
- 直接APIは共通エンジンを使用。汎用CCの旧`removeExisting`挙動から加算方式へ統一した互換変更をREADMEに明記。CC64は範囲内置換を維持。
- 録音は固定120 BPM基準。通常停止、タイムアウト、disposeの保存は一度のみ。結果の永続化は未保存演奏の障害復元を保証しない。
- 既存native環境のCoreMIDI検証と、新規native導入を区別する。後者はXcodeライセンス未承諾で失敗し、承諾や設定変更は行っていない。物理機器・DAW・実際の音・Windowsは未検証。
- スキルのグローバル登録、ユーザーのMCP設定解除、採用manifestの選定と実データ移行は行っていない。

decide_next: 現実装を採用する。今後の候補は、利用者が選んだデータの明示移行、物理機器／DAWでの運用確認、エンジン内の編集サービス整理。自動的な追加変更は行わない。
